# 操作手册：后台、线路、用户怎么用

> 更新时间：2026-11-14
> 对应代码：`npm start`（云端）+ `npm run agent`（设备）+ `src/control/admin-ui.ts`（后台页面）
> **当前状态：云端与后台已在本地跑通；设备侧的 tproxy 数据面尚未在真机验证**

## 1. 三个入口，别搞混

| 入口 | 地址 | 谁用 | 能做什么 |
|---|---|---|---|
| **运营后台** | `http://127.0.0.1:18080/admin` | 你自己/运营 | 看设备、配线路、开账号、切接入模式 |
| **设备门户** | `http://192.168.10.1:8080`（真机） | 客户 | 输账号上网、看当前出口线路、退出 |
| **云端 API** | `http://127.0.0.1:18080/api/admin/*` | 脚本/自动化 | 后台页面调的就是它 |

## 2. 第一次启动

```bash
cd 定制软路由系统

# 启动云端（首次会自动写入演示数据）
npm start
```

启动日志会给三样东西，记下来：

```text
设备 ID     dev-ax3000t-001
注册令牌    <32 位随机串>          ← 设备注册用，两小时有效
管理令牌    dev-admin-token        ← 后台登录用，生产环境必须改
```

改端口/令牌/数据目录：

```bash
LP_CONTROL_PORT=18080 LP_ADMIN_TOKEN='换成你自己的长随机串' LP_DATA_DIR=/var/lib/linkpilot npm start
```

> ⚠️ `LP_ADMIN_TOKEN` 默认是 `dev-admin-token`。**上线前必须改**，它就是后台的唯一钥匙。

## 3. 登录后台

浏览器打开 `http://127.0.0.1:18080/admin`，右上角输入管理令牌 → 点「连接」。

- 令牌存在浏览器 sessionStorage，关掉标签页就没了，下次重输。
- 页面本身不含任何凭证；所有数据都靠 `Authorization: Bearer <token>` 现取。
- 没有令牌一律 401，包括概览页。

## 4. 配线路

后台「线路」区块，填这几项：

| 字段 | 说明 |
|---|---|
| 线路 ID | 唯一标识，建议 `line-地区-序号`，如 `line-us-01`。**建好后别改**，账号绑的是它 |
| 名称 | 客户能看到的线路名，如「美国-洛杉矶-01」 |
| 地区 | 展示用，如 `US` / `HK` |
| 协议 | Shadowsocks / Trojan / VLESS / SOCKS5 |
| 服务器 / 端口 | 你的落地节点地址 |
| 密码 / UUID | SS 密码、Trojan 密码、VLESS UUID |
| SNI / WS 路径 | 走 TLS 或 WebSocket 才需要 |

提交后：

1. 凭证立刻用云端 master key 加密落盘，**之后任何接口都不会再返回明文**；
2. 设备版本号 +1，设备下一轮拉取（默认 30 秒）自动生效；
3. 后台「线路」表里能看到启停状态。

### 粘贴分享链接（推荐：一百台手机用这个）

后台最上面那个框，直接把机场/自建给的链接粘进去，一行一条：

```
ss://YWVzLTI1Ni1nY206cGFzcy0xMjM0NTY=@1.2.3.4:8388#美国-洛杉矶-01
vmess://eyJ2IjoiMiIsInBzIjoi...
vless://uuid-xxxx@jp.example.com:443?security=tls&type=ws&path=/ray&sni=jp.example.com#日本-东京-01
trojan://pass-abcdef@hk.example.com:443?sni=hk.example.com#香港-01
hy2://pass-hy2@1.1.1.1:8443?sni=hy.example.com&insecure=1#日本-02
socks5://user:pass@9.9.9.9:1080#代理A
```

**账号密码有三种给法**（在「账号前缀」右边的「统一密码」框里填）：

| 填什么 | 结果 | 什么时候用 |
|---|---|---|
| 留空 | 每个账号随机生成 10 位（如 `7tcsf6dk49`） | **推荐**。一人一密，泄露一个不影响别人 |
| 统一密码（≥8 位） | 所有账号同一个密码（如 `JYpass-2026`） | 批量交付、客户嫌记不住、或要走统一话术 |
| 想逐个不同又可控 | 先用下面「CSV 方式」导入，`password` 列自己写 | 有既有账号体系要对接 |

密码**只在导入结果里显示一次**，导入完立刻点「复制全部」，格式是 `账号,密码,线路名` 三列。
丢了只能停用重建（密码是 scrypt 哈希，云端也解不出来）。

系统会做这些事：

1. **自动识别协议**：SS / VMess / VLESS / Trojan / Hysteria2 / SOCKS5 / HTTP
2. **自动猜地区**：从备注名或域名里识别香港/美国/日本/新加坡等，猜不到标「未标注」
3. **一条链接 → 一条线路 + 一个账号**（jy001、jy002…），账号绑死这条线路
4. **自动切到账号登录模式**
5. **口令只显示一次**，页面上有「复制全部」，复制出来是 `账号,密码,线路` 三列，可直接发给客户

不支持的协议会明确报错并指出第几行，不会静默跳过：`SSR`、`TUIC`、`AnyTLS`、`Hysteria v1` 目前内核没接。

重复的节点会被跳过——同一个服务器+端口出现两次，等于两个账号共用一个出口 IP，与「一人一 IP」冲突。

实测：粘贴 100 条混合协议链接 → 识别 100 条、新建 100 条线路、生成 jy001–jy100 共 100 个账号。混一条 `ssr://` 时，其余 100 条照常导入，只有那条报错。

### 线路测速

线路表右侧有「测速」，表格底部有「全部测速」。测完每条线路会显示：

- 绿色 `xx ms`：握手成功且延迟低（<200ms）
- 黄色 `xx ms`：成功但偏慢（>500ms）
- 红色「失败」：鼠标悬停看原因（连接超时 / 端口拒绝 / 域名解析失败 / 证书校验失败）

**它测什么、不测什么，必须分清楚：**

| 测得到 | 测不到 |
|---|---|
| 节点端口是否活着 | 凭证（UUID/密码）是否正确 |
| TLS 证书与 SNI 是否匹配 | 客户本地网络到这个节点快不快 |
| 云端到节点的握手延迟 | 实际能不能跑满带宽 |

原因是这一版走的是云端发起的 TCP/TLS 握手。等价于 PassWall「URL 测试」的做法要在设备上临时拉起 sing-box 走一次真实请求，那是下一步。当前这层解决的是**「一百条里哪几条是死的」**——导入完先点一次全部测速，把红的删掉，用户就不会先发现。

一键清死线：测完把红色那几条在后台删掉或停用（停用后对应账号也失效），再让客户上线。

### 批量导入（CSV 方式，需要精确控制时用）

后台「批量导入（CSV 方式）」区块，直接粘贴 CSV（逗号或 Tab 都行，可从表格软件复制）：

**线路**列顺序：`id,name,region,kind,server,port,secret,sni,wsPath`

```
line-us-01,美国-洛杉矶-01,US,shadowsocks,1.2.3.4,8388,pass-123456,,
line-hk-02,香港-02,HK,trojan,hk.example.com,443,pass-abcdef,hk.example.com,
```

- `secret` 按协议解释：SS/Trojan = 密码，VLESS = UUID
- Trojan 必须给 SNI（没有 TLS 连不上），会被直接拒绝并指出行号
- 勾选「覆盖同 ID 线路」才会更新已存在的线路，否则跳过

**账号**列顺序：`username,password,displayName,lineId,expiresAt`

```
c001,pass-123456,客户001,line-us-01,
c002,pass-123456,客户002,line-us-01,2026-12-31
```

逐行返回结果：成功几条、失败几条、第几行错在哪。一百行里错一行，不会整批白导。

## 5. 开接入账号（客户用这个上网）

后台「接入账号」区块：

| 字段 | 说明 |
|---|---|
| 账号 | ≥3 位，全局唯一，客户输的就是它 |
| 密码 | ≥8 位，设备侧 scrypt 校验，明文不落盘 |
| 显示名 | 给自己看的备注，如「客户A-美国」 |
| 线路 | **必选且唯一**，账号 → 线路 = 一人一 IP |
| 到期 | 不填=长期；填了到期后自动降级为「仅门户」 |

规则（已定，不要再改）：

- **一个账号只能同时一台设备在线**，后登踢前登；
- 账号绑死一条线路，登录后出口 IP 恒定；
- 到期后 Wi-Fi 照样能连，但只有门户能打开，页面提示续费。

停用/启用：列表里直接点按钮。停用后设备下一轮同步即撤销会话。

## 6. 切接入模式

「接入模式」区块两个按钮：

- **设备预授权**（默认）：按 MAC 预先授权，适合固定设备、无人值守。原来的玩法。
- **账号登录**：单 SSID，客户自己输账号密码。你要的那个。

切换前有一个硬性检查：**必须先有至少一个启用的接入账号**，否则接口直接 409。理由：没有账号时编出来的配置没有任何分流入口，用户连上网会「Wi-Fi 已连接但完全打不开」，比不改更糟。

宽限期默认 5 分钟，只影响「离线多久后名额释放」，不影响通断。

## 6.5 一百台手机能不能撑住

已实测：导入 100 个账号后编译产物仍是 **2 个入站、114 行防火墙规则**——因为入站按线路算，不按设备算。这是 per-line tproxy 设计的直接收益：设备数从 10 涨到 100，代理配置一行没变。

但有三个硬约束，别忽略：

| 约束 | 现在的值 | 说明 |
|---|---|---|
| 线路与账号 | 一条线路对一个账号 | 100 台手机 = 100 条线路 = 100 个出口 IP。若一条线路挂多个账号，后台会标黄「共用出口 IP」 |
| DHCP 地址池 | `192.168.10.50 – .250`，**201 个** | 100 台手机 + 电脑 + AP 够用。后台会实时算「地址池 / 启用账号」，不够会标红 |
| AP 带机量 | 雅典娜官方宣称 253 台 | 100 台在范围内，但**实测带机 100 台 + 视频流**没做过 |
| 出口带宽 | 由你的线路决定 | 100 台同时看视频肯定不够。这不是软件问题，是卖的时候就要按带宽配比 |

还有一条产品规则要盯住：**一条线路挂多个账号 = 共用同一个出口 IP**。后台会在「接入模式」那行标黄提示「N 条线路被多个账号共用」。如果你承诺「一人一 IP」，就得一条线路对一个账号，线路数量要跟账号数量匹配。

## 6.6 局域网访问

| 服务 | 默认监听 | 局域网能访问吗 | 怎么开 |
|---|---|---|---|
| 设备门户（客户用） | `0.0.0.0:8080`（需 `LP_DRY_RUN=0`） | ✅ 能 | nftables 的 input 链已放通 `br-lan → 8080/8081`，无需额外操作 |
| 运营后台 | `127.0.0.1:18080` | ❌ 默认不行 | 启动时加 `LP_CONTROL_HOST=0.0.0.0` |

打开局域网后台：

```bash
LP_CONTROL_HOST=0.0.0.0 LP_ADMIN_TOKEN='<长随机串>' npm start
# 然后手机/电脑访问 http://<云端或N100的IP>:18080/admin
```

> ⚠️ 后台只有一把令牌，没有多用户也没有 TLS。绑 `0.0.0.0` 只适合内网/办公网；放到公网前必须加反向代理 + HTTPS，否则等于把线路凭证的加密钥匙挂在门口。

## 7. 设备侧怎么接（真机）

完整步骤见 **`docs/ops/N100部署手册.md`**。装完 Debian 后其实只有一条命令：

```bash
sudo bash /opt/linkpilot/scripts/install.sh
```

它会自动装 Node 22、sing-box、配网桥与 DHCP、装 systemd 服务、启动并自检；默认云端与网关同机，注册令牌自动读取，不用人肉复制。跑完直接给门户地址和后台地址。

之后日常只用 `linkpilot status | check | logs | restart`。

> 验证阶段用 Debian（Node 22 即装即用），量产再换 OpenWrt。原因：OpenWrt 软件源没有 Node 22，官方二进制是 glibc 构建跑不了 musl——这是量产前必须先解决的技术债。

AP（雅典娜）侧：AP 模式、关 DHCP、关 IPv6、关积分、关自动升级、**关客户端隔离**（要互访），见 `10` 号文档 §14/§15。

## 8. 用户怎么用（完整链路）

```text
① 手机连 Wi-Fi（唯一那个 SSID，密码由 AP 提供）
② 系统自动弹「需要登录」——靠 80 端口劫持 + 53 端口应答器
   （没弹窗就手动打开任意 http 网站，会跳到登录页）
③ 输账号密码 → 点「连接」
④ 页面显示「已连接 · 出口线路 美国-洛杉矶-01」
⑤ 此时起，这台手机的所有流量走该线路，出口就是这条线路的公网 IP
⑥ 客户自己去 ip.sb 查，看到的应该是同一个 IP
⑦ 换号：页面点「退出登录」，再输另一个账号
   只有这台设备的连接受影响，其他人在线不受影响
```

门户会记住设备（按 MAC）。锁屏、走开再回来、网关重启，都**不需要重新输密码**——只有换账号、被踢、换新手机才要重登。

编码器/NVR 这类没有浏览器的设备：不走登录，走预授权（按 MAC 绑线路），配好后插上就能用。

## 9. 出问题先看这三条

| 症状 | 先查什么 |
|---|---|
| 连上 Wi-Fi 不弹登录页 | 53 端口应答器起没起（日志有 `[portal-dns] 已监听`）；80 劫持规则在不在（`nft list chain inet linkpilot dns_hijack`） |
| 登录成功但所有网站打不开 | **tproxy 策略路由**：`ip rule show` 里有没有 `fwmark 0x1 lookup 100`；没有就是流量黑洞 |
| 登录后 IP 没变 | 会话表有没有写进去：`nft list set inet linkpilot authed_v4`；再看门户的 `access-state` |
| 一个人登录，别人都断了 | 不该发生。若发生说明走到了「重编译 + 重启 sing-box」那条路，检查是否误用了设备绑定模式 |
| 一账号两台设备互相顶 | 正常行为，后登踢前登 |

## 10. 现在还不能做的（别在客户面前承诺）

1. **后台没有真正的登录体系**：令牌即钥匙，没有多用户、MFA、操作日志页面（接口有审计，页面没展示）。
2. **没有探针与自动切线**：主备切换是纸面功能，线路挂了要人工切。
3. **单租户**：一套云端管一个组织，多客户要分实例。
4. **100 台是算出来的，不是测出来的**：编译规模和地址池够，但真机 100 台并发没压测过。
5. **真机未验证**：tproxy + 策略路由 + DNS 劫持这一整套，一次都没在真 OpenWrt 上跑过。
