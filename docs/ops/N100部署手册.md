# N100 部署手册（从空机到能上网）

> 更新时间：2026-11-14
> 适用：Intel N100 小主机（x86_64）+ 外置 AP（京东云雅典娜）
> 系统：**Debian 13.7 amd64 netinst**（13.x 任意维护版均可，12.15 LTS 亦可）
> 前置阅读：`docs/design/10-N100-系统基线与稳定性设计.md`

## 0. 一句话版本

装完 Debian，把仓库拷到 `/opt/linkpilot`，然后：

```bash
sudo bash /opt/linkpilot/scripts/install.sh
```

回答两个问题（云端是否同机、确认网口），剩下的它全做完：依赖 → Node 22 → sing-box → 云端 → 网络基线 → 系统服务 → 启动 → 自检。

**为什么先装 Debian 而不是 OpenWrt**：OpenWrt 软件源里没有 Node 22，官方 Node 二进制是 glibc 构建、在 musl 上跑不起来。验证阶段用 Debian 能当天跑通；量产再换 OpenWrt（差异见 §9）。这条不要反过来做。

## 1. 硬件与 BIOS

- N100 小主机（4 网口最好）、≥64G SSD、U 盘（≥4G）、显示器键盘（只用于装系统）
- BIOS 必改项：

| 设置 | 值 | 原因 |
|---|---|---|
| Restore on AC Power Loss | **Power On** | 客户现场断电后来电必须自启 |
| Secure Boot | Disabled | 避免引导被拦 |
| ASPM / PCIe 节能 | **Disabled** | i226 网卡不定时掉链的头号原因 |
| 深度 C-state | 限制 C1/C3 | 同上 |
| PXE / 网络启动 | 关闭并移出启动项 | 防止插网线误进 PXE 失联 |
| 硬件看门狗 | 开启（若支持） | 死锁时唯一自救手段 |

## 2. 下载与写 U 盘

### 2.1 下载哪个版本

**Debian 13.7 amd64 netinst**（当前稳定版，代号 trixie，内核 6.12——对 N100 的 i226 网卡支持比 12 的 6.1 好）。

> 维护版号会往前走（13.6 → 13.7 → …），下载页上给的是哪个就用哪个，装完 `apt upgrade` 也会补齐。下面以 **13.7** 为例。

| 选项 | 选它吗 | 说明 |
|---|---|---|
| `debian-13.7.0-amd64-netinst.iso` | ✅ **就这个** | 约 756MB，安装时从网络拉包 |
| `debian-12.15.0-amd64-netinst.iso` | 可以用 | 12 系列已进入 LTS，这是最后一个常规维护版；脚本同样兼容 |
| `...-DVD-1.iso` | ❌ | 4.7G，只有完全离线装机才需要 |
| `...-live-amd64-*.iso` | ❌ | Live 镜像是拿来体验的，安装流程不一样 |
| `arm64` / `armhf` | ❌ | N100 是 x86_64 |

下载地址（国内用镜像站快很多）：

```text
官方：    https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/
清华：    https://mirrors.tuna.tsinghua.edu.cn/debian-cd/current/amd64/iso-cd/
中科大：  https://mirrors.ustc.edu.cn/debian-cd/current/amd64/iso-cd/
```

文件名形如 `debian-13.7.0-amd64-netinst.iso`。

**校验一下**（U 盘写坏是装机最常见的坑，别省这 10 秒）：

```bash
# Linux / macOS
shasum -a 256 debian-13.7.0-amd64-netinst.iso
```

```powershell
# Windows PowerShell
Get-FileHash .\debian-13.7.0-amd64-netinst.iso -Algorithm SHA256
```

结果跟同目录 `SHA256SUMS` 里那一行对比，一致再写盘。

### 2.2 写 U 盘

**Windows：Rufus**（推荐，比 Etcher 稳）

1. 插 U 盘（≥4G，**会被清空**）
2. Rufus → 设备选 U 盘 → 选择下载的 ISO
3. 分区类型 **GPT**、目标系统 **UEFI**
4. 点「开始」→ 若弹出「ISOHybrid 镜像检测」，选 **「以 DD 镜像模式写入」**
   （Debian 官方推荐，避免 Rufus 改写引导后装不上）
5. 等进度条走完

**三平台通用：balenaEtcher**

选 ISO → 选 U 盘 → Flash。一个界面走完，不容易点错。

**Linux / macOS 命令行**

```bash
lsblk                                   # 先确认 U 盘是 /dev/sdX，别看错盘
sudo dd if=debian-13.7.0-amd64-netinst.iso of=/dev/sdX bs=4M status=progress oflag=sync conv=fsync
sync
```

> `of=/dev/sdX` 写的是整块盘。写错就是抹掉系统盘，执行前再 `lsblk` 看一眼容量。

### 2.3 从 U 盘启动

1. N100 插 U 盘，开机连按 `F7`/`F11`/`F12`（各家不同）进启动菜单
2. 选带 **`UEFI:`** 前缀的那个 U 盘项
3. 出现 Debian 菜单 → 选 **`Install`**（不用 Graphical install）

启动菜单里看不到 U 盘：

- BIOS 关掉 Secure Boot，启动模式设为 UEFI only
- 换个 USB 口（有的机器前面板口不引导）
- 重写一次 U 盘（大概率是 DD 模式没选对）

### 2.4 安装时的关键选择

| 步骤 | 选什么 | 为什么 |
|---|---|---|
| 主机名 | `linkpilot-gw` | 一眼认得出 |
| root 密码 | **留空** | 自动禁用 root 登录，改用 sudo，少一个被爆破的口子 |
| 分区 | 向导 → 使用整个磁盘 → 全部放一个分区 | 验证阶段够用；量产走固件 A/B |
| 镜像站 | 中国 → 清华 / 中科大 | 装包快十几倍 |
| 软件选择 | **只勾 `SSH server` + `standard system utilities`** | 不要桌面，省 800MB 内存和一堆用不上的服务 |

装完拔 U 盘重启，用安装时建的普通用户登录：

```bash
sudo apt update && sudo apt install -y sudo curl vim
sudo timedatectl set-timezone Asia/Shanghai
# 关休眠：网关休眠等于断网
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

## 3. 一键部署

把仓库放到 N100（git clone 或 scp 整个目录到 `/opt/linkpilot`），然后：

```bash
sudo bash /opt/linkpilot/scripts/install.sh
```

它会问两个问题：

```
云端和网关是否跑在同一台机器上？
  y = 是（最省事，本机既管设备又做网关）  ← 推荐先这样
  n = 否（已有独立云端，等下填地址和令牌）
```

```
将把 enp2s0 enp3s0 建成网桥、网关设为 192.168.10.1，继续？[Y/n]
```

WAN 口是自动识别的（看默认路由走哪个口），LAN 是其余的 `en*`/`eth*`。识别错了可以用参数指定：

```bash
sudo bash scripts/install.sh --wan enp1s0 --lan "enp2s0 enp3s0" --yes
```

跑完会打印一段总结，含**客户门户地址、运营后台地址、管理令牌**。管理令牌是随机生成的，记下来。

非交互方式（脚本化/重复部署）：

```bash
sudo bash scripts/install.sh --local-cloud --yes
sudo bash scripts/install.sh --cloud http://1.2.3.4:18080 --token xxxx --yes
```

## 3.5 从 GitHub 拉取部署（推荐）

代码在 **`https://github.com/jiujiu025/linkpilot`（公开仓库）**。

**A. 一条命令（推荐）**

```bash
sudo bash -c 'apt-get install -y git >/dev/null 2>&1; git clone --depth 1 https://github.com/jiujiu025/linkpilot.git /opt/linkpilot && bash /opt/linkpilot/scripts/install.sh'
```

**B. 分两步，出错更容易看**

```bash
sudo apt-get install -y git
sudo git clone --depth 1 https://github.com/jiujiu025/linkpilot.git /opt/linkpilot
sudo bash /opt/linkpilot/scripts/install.sh
```

**C. curl 直拉（部分网络对 raw.githubusercontent.com 不通，失败就用 A/B）**

```bash
curl -fsSL https://raw.githubusercontent.com/jiujiu025/linkpilot/main/scripts/bootstrap-remote.sh | sudo bash
```

**更新已部署的机器**：

```bash
linkpilot update      # git 对齐远端 + 重启 Agent
```

`update` 只拉代码不碰数据（`/var/lib/linkpilot` 与 `/etc/linkpilot` 在仓库之外），配置和令牌不会丢。

> 仓库现在是**公开**的，方便一行命令部署。代价是 `docs/` 里的产品设计与运营口径对所有人可见。要收回：
> `gh repo edit jiujiu025/linkpilot --visibility private`（之后部署需改用 token 方式）。

## 4. 验证（四步，缺一步别往下走）

**① Agent 与云端都在跑**

```bash
linkpilot status
```

日志应看到 `注册成功 deviceId=...` → `r1 应用成功`。

**② 防火墙真的装上了**

```bash
linkpilot check
```

应看到 `table inet linkpilot`、会话集合、以及 10000/10001 端口在听。

**③ 后台能用**

浏览器打开总结里给的**运营后台**地址 → 输管理令牌 → 粘贴一百条线路 → 自动生成 jy001–jy100 → 点「全部测速」把红色停用。

**④ 手机实测**

连 AP 的 Wi-Fi → 应自动弹登录页 → 输 `jy001` + 密码 → 页面显示「已连接 · 出口线路 X」→ 手机浏览器访问 `ip.sb`，IP 应该就是这条线路的出口。

## 5. AP 侧（雅典娜）

后台 `jdcloudwifi.com`（连它的 Wi-Fi 或用网线）：

1. **路由设置 → 上网设置 → 工作模式切换 → 有线 AP 模式**
2. 上联网线插 AP 的 WAN 口，另一端插 N100 的 LAN 口
3. 关闭 IPv6
4. App 里退出积分插件、关边缘计算、模式选「上网优先」、上行限值压到最低
5. **关闭客户端隔离**（要同网段互访）
6. 关闭自动升级，信道固定（不要 Auto）

## 6. 断电测试（交付前必做）

```bash
sudo systemctl enable sing-box linkpilot-agent   # 确认开机自启
# 直接拔电源，等 30 秒再插
```

预期：自启 → 日志出现 `开机防火墙 已恢复` → 再连云端拉配置 → 手机不需要重新登录。

这一条不过就别交付。

## 7. 日常运维就四条命令

```bash
linkpilot status     # 三个服务 + 网络
linkpilot check      # 防火墙、会话表、监听端口
linkpilot logs       # 跟踪 Agent 日志
linkpilot restart    # 重启 Agent
```

改了 `/etc/linkpilot/agent.env` 之后要 `sudo systemctl restart linkpilot-agent` 才生效。

## 8. 分步部署（一键脚本失败时用）

一键脚本本质是下面两个脚本的组合，出问题时分开跑更容易定位：

```bash
# 只做网络
sudo bash scripts/network-baseline.sh enp1s0 enp2s0 enp3s0
# 只做运行时与服务（不碰网络）
sudo REPO_DIR=/opt/linkpilot LP_CLOUD_URL=http://127.0.0.1:18080 \
     LP_ENROLL_TOKEN=xxxx bash scripts/bootstrap-debian.sh
```

两者都幂等，可以重复跑。

## 9. 量产换 OpenWrt 时的差异

| 项 | Debian 现状 | 换 OpenWrt 后 |
|---|---|---|
| 网络配置 | `install.sh` 建 br0 + dnsmasq，并装 `linkpilot-network.service` 开机重放（ip 命令不持久化） | 由编译产物 `apply.uci.sh` 接管，`LP_ALLOW_NO_UCI` 必须改回 0（去掉放行） |
| 防火墙 | 开机由 Agent 恢复 active 版本 | 同上，另加 procd 依赖保证 nft 早于 network |
| 根文件系统 | 可写 | squashfs 只读 + overlay，恢复出厂=清 overlay |
| 升级 | 替换代码 + 重启 | A/B 双槽 + boot counter（`10` 号文档 §4） |
| Node 运行时 | 官方包 | **待解决**：预编译 JS 配老版 node，或用 musl 构建产物 |

最后一行是量产前必须解决的技术债。

## 10. 排障表

| 症状 | 查什么 |
|---|---|
| `install.sh` 报 Node 下载失败 | 机器没外网；离线把 `node-v22.x-linux-x64.tar.xz` 放 `/tmp/node.tar.xz` 再跑 |
| 服务起来又挂 | `journalctl -u linkpilot-agent -n 50`；Node 版本 <22.18 会直接语法错 |
| 日志 `uci-apply failed` | 网络被 `--skip-network` 跳过却没配；`LP_ALLOW_NO_UCI` 应为 1 |
| 手机连上没有 IP | `systemctl status dnsmasq`；`ip -br addr show br0` |
| 有 IP 不弹登录页 | `ss -lnpu \| grep :53`；`nft list chain inet linkpilot dns_hijack` |
| 登录成功网页全打不开 | `ip rule show` 里有没有 `fwmark 0x1 lookup 100`——没有就是流量黑洞 |
| 登录后 IP 没变 | `nft list set inet linkpilot authed_v4` 是否为空 |
| sing-box 起不来 | `journalctl -u sing-box -n 50`；多半是配置字段与内核版本不匹配 |
| 网口不定时断 | BIOS 关 ASPM + `ethtool --set-eee <if> eee off` |
