## 2. 已验证的内容（可复现）

`npm test` 共 48 项，全部通过。覆盖：

- 编译器：摘要稳定、设备级分流、cn 直连、过期绑定、缺凭证拒绝、协议不匹配拒绝、绑定冲突拒绝、空授权可用；
- 锁线：按设备生效、不影响同组其他设备、锁到不存在线路时回落并告警；
- 不变量：final 被改、兜底拒绝被删、转发链放开、DNS 劫持被删、IPv6 表被删、凭证写进 UCI、设备失去路由规则——逐项能被拦住；
- 安全：错误令牌、令牌复用、无签名、伪造签名、nonce 重放、请求体篡改、bundle 正文篡改、错误公钥、过期包、版本不递增、bundle 不含明文凭证、非白名单命令、缺少操作原因、跨设备确认命令；
- 硬件档位（2026-11-14 补）：x86 档位按设备档案生成 `br-lan` 网桥与 WAN 口 device 段；ARM 档位不生成 device 段以免与设备树冲突；**缺少 `uci` 时判失败并停手**（此前记 `skipped` 继续跑，会把"没配网络"伪装成成功）。

`npm run demo` 跑通：注册 → 首次下发并应用 → 远程授权 → 二次下发 → 门户登录（含错误口令拒绝）→ 手动切线 → 非白名单命令拒绝 → 审计 → 云端断线后本地继续工作。

## 3. 未验证、必须在真机确认的

| 项 | 为什么必须要真机 | 判定方式 |
|---|---|---|
| `sing-box check` 通过 | 本机没有 sing-box 二进制，`applyArtifacts` 会记为 `skipped` | 真机首次应用时 `singbox-check` 必须为 `ok` |
| `nft -c -f` 通过 | 同上 | 真机 `nftables-check` 必须为 `ok` |
| DNS 劫持是否真的把查询送进 tun | 依赖 `dnat to <tun-peer>:53` + `hijack-dns` 的配合，只有真流量能证明 | 客户端 `dig` 外部域名，抓 tun 与 nft counter |
| 单 SSID 下随机 MAC 的设备识别 | 门户按 IP/主机名/MAC 摘要识别，随机 MAC 会降置信度 | 用手机与编码器各接一次，看是否误判 |
| 代理吞吐与 CPU/温度 | MT7981B 双核 1.3GHz，加密吞吐是最大风险 | 编码器持续上传 + 全局代理，记录 CPU、温度、抖动 |
| 切线对直播的影响 | 换出口必然改源地址，已有连接不保证存活 | 主线路断开，记录「新连接恢复时间」与「直播中断时长」 |
| IPv6 是否彻底关闭 | 需要 WAN/DHCPv6/RA 三层都关闭 | 客户端 `ip -6 addr` 为空，外部 IPv6 探测不通 |
| 云端断线 24h 表现 | 本地缓存、绑定有效期、失败版本拉黑的实际行为 | 拔掉云端，观察网关与切线是否继续工作 |

## 4. 已知技术债

1. **存储是 JSON 文件**：单进程安全，多实例不安全。换 PostgreSQL 时只需替换 `Store`。
2. **nonce 窗口在内存**：多实例部署要换 Redis `SETNX`。
3. **控制面没有管理员会话体系**：当前是 Bearer token，生产要换 OIDC + MFA。
4. **探针缺失导致 `health` 字段偏乐观**：现在只根据「是否应用过配置」和「云端可达性」判断。
5. **锁线不写过云端**：手动锁线是设备本地状态，云端 `ObservedState` 看不到，Phase 5 应补成显式状态字段。
6. **门户的 Wi-Fi 口令修改只到配置下发**：真正落 hostapd 需要 OpenWrt Helper，当前命令回 `QUEUED`。
7. **schema 新增带默认值的字段会改变摘要**：云端算摘要前必须过 `DesiredState.parse` 规范化（`buildBundle` 已修正），否则存量设备会集体 `DIGEST_MISMATCH`。这类改动要按"协议变更"对待，不能当普通加字段。
8. **x86 网口角色仍需人工确认一次**：`lanPorts` / `wanPort` 目前靠设备档案手填，`hardware.ts` 还没做接口指纹探测（见设计 10 §6，V1 补）。
