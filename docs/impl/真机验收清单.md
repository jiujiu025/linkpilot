# 真机验收清单（小米 AX3000T）

> 前提：设备身份、硬件版本、原厂备份与恢复路径已按 `docs/design/09` 确认。
> **本清单不授权刷机。** 任何写入设备、恢复出厂、改启动参数的动作都要另行批准。
> 记录里禁止出现密码、UUID、私钥、完整节点地址。

## 0. 上机前

- [ ] 铭牌型号 / 区域 / 硬件版本已拍照存档，序列号只留脱敏摘要
- [ ] 原厂固件只读备份完成，大小与摘要已记录
- [ ] 恢复入口（Web / 按键 / TFTP / 串口）已实际走通一次
- [ ] 目标 OpenWrt 版本已确认支持该硬件版本
- [ ] 一台有线编码器 + 一台无线终端 + 一条真实线路可用
- [ ] 云端控制面可访问（内网即可，先不暴露公网）

## 1. 基础数据面（Phase 1）

```bash
# 设备侧
node src/agent/main.ts          # LP_CLOUD_URL / LP_ENROLL_TOKEN 指向测试控制面
```

- [ ] Agent 注册成功，云端 `GET /api/admin/overview` 能看到设备，`state=active`
- [ ] 终端连上单 SSID，拿到 `192.168.10.x`
- [ ] 未授权终端打开 `http://192.168.10.1:8080` 能出门户，`curl ifconfig.me` 超时
- [ ] 未授权终端之间互 ping 不通（`client_isolation` 生效）
- [ ] 修改 Wi-Fi 口令后，无线终端短暂断开并能用新口令重连
- [ ] `ip -6 addr` 在客户端为空；`curl -6 ifconfig.co` 不通

失败判定：出现「未授权终端能出公网」或「客户端能访问代理端口」，直接判该轮不通过，不用继续。

## 2. 分流与防泄露（Phase 3）

| 检查 | 命令 | 期望 |
|---|---|---|
| 出站 IP | `curl ifconfig.me` | 等于当前线路出口 IP，不是本地宽带 IP |
| DNS 劫持 | `nft list chain inet linkpilot dns_hijack` | 有 `dnat ip to 172.19.0.2:53` 且 counter 在涨 |
| DNS 泄露 | `dig +short txt o-o.myaddr.l.google.com @8.8.8.8` | 解析结果来自受控出口，不是本地 ISP |
| DoT 阻断 | `dig +tls @1.1.1.1 example.com` | 连接被拒 |
| 未匹配流量 | `curl --interface eth0 http://<任意外网IP>` | 不通（forward 默认 drop） |
| IPv6 | `curl -6 https://ifconfig.co` | 不通 |
| 严格全局 | 停掉代理核心 `pkill sing-box` | 公网立即不通，门户仍可访问 |
| 恢复 | 重启代理核心 | 公网恢复，且不需要重下配置 |

- [ ] sing-box 配置 `sing-box check -c singbox.json` 通过
- [ ] `nft -c -f nftables.nft` 通过
- [ ] `applyArtifacts` 的 `nftables-check` / `singbox-check` 两步均为 `ok`（不是 `skipped`）

## 3. 设备授权与锁线（Phase 2）

- [ ] 编码器接入后出现在「待授权设备」，只显示 IP、主机名、MAC 后四位
- [ ] 门户授权后 30 秒内出口切换成功，编码器 `curl ifconfig.me` 返回新出口
- [ ] 授权有效期到期后自动回收（把 `validUntil` 设成 1 分钟后观察）
- [ ] 手动锁线只影响目标设备：同组另一台设备的出口不变（`manifest.json` 里逐台可查）
- [ ] 撤销设备后，该设备立刻断网，且不再出现在 nftables `authorized_v4`

## 4. 直播压力（Phase 3 / 验收）

记录组合（每档至少 30 分钟）：

- [ ] 空载基线：CPU / 内存 / 温度
- [ ] 单设备有线长连接上传（目标码率 +20%）
- [ ] 双设备并发（一路上行直播 + 一路下载）
- [ ] 探头测速并行（观察是否抢直播带宽）
- [ ] 主线路断开 → 切线 → 恢复

需要记录的字段：

```
码率        上行/下行实测 Mbps
CPU         每核心利用率、是否降频
内存        峰值 / 是否 OOM
温度        SoC / 外壳
丢包与抖动  直播端统计为准
切线        新连接恢复时间、直播中断时长
```

- [ ] 连续 72 小时无 OOM、无代理崩溃、无未授权直连、无频繁切线

## 5. 云端故障（Phase 4）

- [ ] 停掉控制面 30 分钟：本地转发、DNS、门户、切线逻辑全部继续工作
- [ ] 控制面恢复后 Agent 自动重连，不需要重启
- [ ] 应用坏配置（人为写坏 `nftables.nft`）→ 应用失败 → 保持上一版本
- [ ] 同一坏版本重复下发 → Agent 拒绝应用（`failedRevisions` 生效）
- [ ] `ROLLBACK_CONFIG` 命令可回到上一稳定版本

## 7. 不可妥协的红线

任一条件出现，本轮验收直接判不通过，不允许用「调低安全等级」来换取通过：

- 代理停止后存在任何普通 WAN 直连路径；
- 客户端能绕过受控 DNS 拿到外部解析结果；
- 未授权设备能访问公网或其他客户设备；
- 云端能执行任意 Shell，或接受未签名/过期/重放命令；
- 日志、诊断包、门户响应中出现线路凭证或口令哈希；
- 配置应用失败后没有回到上一稳定版本。
