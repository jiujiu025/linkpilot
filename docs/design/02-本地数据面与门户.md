# 本地数据面与门户

## 1. 本地数据面分层

```text
品牌化门户 UI
  → 本地认证和 DeviceSession
  → Router Agent 本地受限接口
  → 策略编译器和状态数据库
  → nftables、ip rule、路由表、DNS
  → 执行器适配器
  → sing-box / Xray / WireGuard
  → WAN
```

本地状态存储只保存运行所需的最小数据，例如设备会话、绑定状态、版本摘要、健康状态和撤销列表。业务主数据以云端为准，但云端断开时要保留已授权状态直到本地有效期结束。

## 2. OpenWrt 边界

- `netifd`：WAN、PPPoE、接口和链路状态。
- `hostapd`：单 SSID、WPA2/WPA3 和客户端接入。
- `dnsmasq` 或等效服务：DHCP、局域网解析和门户相关解析。
- `nftables`：客户端隔离、流量标记、DNS 强制接管、Kill Switch。
- `ip rule`/策略路由：按设备或流量标记选择线路表。
- `procd`：Agent、探针、代理核心和本地服务守护。
- `openNDS` 或等效组件：Captive Portal 引导和认证放行。

OpenWrt 配置由受限适配器管理，不允许客户直接修改底层 UCI、nftables 或代理核心配置。

## 3. 单 SSID 与本地认证

### 正常流程

```text
终端连接 LinkPilot-WiFi
  → DHCP 获得地址
  → 本地识别为未认证或已授权
  → 未认证终端仅能访问本地门户
  → 用户登录
  → 服务端返回权限和可用 RouteProfile
  → 创建 DeviceSession
  → 编译设备级标记和放行规则
  → 终端获得对应公网访问能力
```

本地门户固定提供 `http://router.local` 和固定网关地址。mDNS 只作为便利入口，不能作为唯一入口。

不得粗暴劫持所有 HTTPS 请求；应使用终端连通性检测、HTTP 引导和手动地址，避免证书错误。

## 4. 客户与设备管理员体验

统一登录入口不要求用户先选择角色。登录后由服务端返回能力集合：

- 客户用户：查看自身服务、设备状态、线路状态、基础流量和公网出口 IP。
- 设备管理员：除上述内容外，可管理绑定的单台软路由、Wi-Fi、待授权设备、设备线路绑定和线路切换。

页面不出现 OpenWrt、PassWall、Xray、sing-box、UUID、私钥、完整节点地址或订阅链接。

修改 Wi-Fi 密码、立即切线、撤销设备和进入维护模式等操作必须重新验证登录密码或二次认证，并显示可能的中断影响。

## 5. 直播设备远程授权和线路绑定

### 5.1 设备发现

设备通过 DHCP 后进入 `PENDING_AUTHORIZATION`：

- 采集主机名、IP、MAC 哈希、接入时间、连接接口、在线状态和流量摘要。
- 页面只展示 MAC 后四位或其他不可逆脱敏标识。
- 设备标识使用租户、RouterDevice、接口、MAC 哈希和时间窗口组合，避免单一字段误认。
- 对随机 MAC 和二次 NAT 场景标记为低置信度，要求有线接入或人工确认。

### 5.2 授权流程

```text
设备上线
  → 本地进入待授权隔离区
  → 客户/设备管理员登录门户
  → 选择设备并确认设备特征
  → 选择已授权 RouteProfile
  → 校验账号、设备、租户、线路有效期和并发限制
  → 创建 DeviceRouteBinding
  → 生成本地策略版本
  → 应用设备级流量标记
  → 探针验证 DNS、代理出口和目标访问
  → 成功后状态变为 AUTHORIZED
```

### 5.3 云端远程授权

云端运营管理员选择指定 `RouterDevice` 和待授权设备，提交带原因的固定命令。Agent 只接受目标设备、版本、过期时间、Nonce、幂等键和数字签名均有效的命令。

远程授权不要求访问客户电脑，不下发客户密码，也不回传线路明文凭证。命令完成后只上报脱敏设备标识、结果码、配置版本和探针摘要。

### 5.4 绑定约束

- 一个设备同一时刻只能有一个生效的主 RouteProfile。
- 备用线路属于同一 FailoverPolicy，不能由客户端绕过策略直接选任意线路。
- 绑定包含生效时间、过期时间、撤销时间、操作者和版本号。
- 线路切换采用乐观锁或租约锁，避免门户、后台和自动切线同时写入造成竞态。
- 连接级线路选择保持粘滞，不做逐数据包跨线路负载均衡。
