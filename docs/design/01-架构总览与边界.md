# 架构总览与边界

## 1. 设计思路

系统先划分不可混淆的边界，再定义数据流：

```text
客户终端
  → 本地门户和会话授权
  → 本地策略编译结果
  → nftables / policy routing / DNS
  → sing-box、Xray 或 WireGuard
  → WAN 线路

云端后台
  → Desired State、固定命令和配置版本
  → Router Agent 主动出站连接
  → 本地受限适配器
  → Observed State、探针和审计结果
```

实时流量永远不经过云端。云端不可用时，设备继续使用最后一个稳定配置、已授权会话和本地故障切换逻辑。

## 3. 模块边界

### 3.1 设备侧

| 模块 | 责任 | 不负责 |
|---|---|---|
| OpenWrt 基础层 | WAN、LAN、Wi-Fi、DHCP、系统服务、启动和进程守护 | 业务权限和云端资源管理 |
| 本地门户 | 登录、会话、待授权设备展示、客户可见状态 | 读取线路明文凭证、任意系统配置 |
| Router Agent | 身份、配置拉取、签名校验、固定命令、状态上报 | 任意 Shell、直接暴露数据库 |
| 策略编译器 | 将业务策略编译为本地规则和执行器配置 | 在数据包路径查询云端或数据库 |
| 代理适配器 | 生成并管理 sing-box/Xray/WireGuard 所需运行配置 | 决定客户权限 |
| 防火墙/路由 | 默认拒绝、标记、分流、Kill Switch | 保存业务凭证 |
| 本地探针 | 本地链路、协议、出口和资源检查 | 代替云端跨区域观测 |

### 3.2 云端

建议使用 Modular Monolith + Worker：

- API 层：认证、租户、资源、设备、线路、策略和运维接口。
- 配置域：Desired State、编译、版本、签名和部署编排。
- 设备连接域：Agent 心跳、消息、命令幂等和连接状态。
- 探针域：采集、聚合、告警、事件和诊断结论。
- 运维域：OTA、模拟客户门户、工单和审计。
- Worker：异步编译、部署、探针聚合、OTA 分发和过期任务清理。

V1 不拆成大量微服务，避免分布式一致性和排障复杂度提前增加。

## 4. 需求冲突与推荐决策

### 冲突 A：单 SSID、强制登录与无浏览器设备

编码器和摄像机无法完成 Captive Portal 登录，若强制所有设备自行登录，会无法使用。

推荐方案：

1. 人类终端通过本地门户登录，建立账号级会话。
2. 无浏览器设备先进入“待授权”隔离区，只能访问 DHCP、门户和必要局域网协议。
3. 客户或设备管理员在门户中选择待授权设备并绑定 RouteProfile。
4. 授权结果由本地策略编译器转换为设备级标记；设备本身不需要登录。
5. 优先使用有线接入；无线设备使用脱敏 MAC、IP、主机名、接入时间和 AP 信息组合识别。

这保持单 SSID 方向，同时不依赖设备具备浏览器。

### 冲突 B：客户账号绑定线路与设备级流量转发

网络设备通常按源地址、接口或标记转发，不能可靠地让每个数据包实时查询账号数据库。

推荐方案：账号登录只负责创建或更新 DeviceSession；会话随后映射到设备级、端口级或地址级策略标记。数据包路径只读取编译后的本地集合和路由表。

### 冲突 C：主备切线与直播长连接无感恢复

切换出口通常会改变源地址，已有 TCP、UDP 或 QUIC 连接不保证继续有效。

推荐方案：对新连接快速切换，对已有连接提供连接粘滞和可选的立即切换；产品文案明确可能中断当前直播，不能承诺完全无感。

### 冲突 D：兼容 PassWall 与不依赖 PassWall

PassWall 是配置界面和生态集合，不是稳定的业务抽象，协议列表随版本和底层核心变化。

推荐方案：建立 `ProtocolProfile` 和 `ExecutorAdapter` 抽象。支持导入或人工录入 PassWall 常见协议参数，但由 sing-box、Xray 或 WireGuard 适配器生成实际配置。

## 5. 不可变安全边界

- 本地门户不提供 LuCI、SSH、Telnet、Shell、原始配置和任意防火墙编辑。
- 云端不下发任意 Shell，只能下发固定命令和签名配置。
- 客户页面只展示脱敏线路名称、地区、状态和公网出口 IP。
- 线路明文凭证只在密钥管理系统、受限配置编译器和设备安全存储中短暂存在。
- 数据面不依赖云端实时可用性。
- 配置应用必须具备校验、签名、原子写入、健康验证和自动回滚。
