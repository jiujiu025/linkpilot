# N100 + 三 AP 组网与系统方案

> 状态：系统层已可交付（`image/`，可构建 x86_64 固件）；AP 侧为通用配置方案，**具体型号待确认**。
> 适用：N100 软路由作网关（本机无无线），3 台 AP 作纯二层接入。

## 1. 一句话结论

**N100 当唯一的网关与出口，3 台 AP 全部工作在桥接（AP/Bridge）模式，只提供二层接入。**
代理、分流、Kill Switch、门户、DHCP、DNS 全在 N100 上；AP 不路由、不 NAT、不发 DHCP、不广播 IPv6。

这不是审美选择，是被架构逼出来的：Agent 的分流按**源 IP**（`source_ip_cidr`）匹配。任何一台 AP
一旦做 NAT，客户端源地址在 N100 看来全是 AP 自己的地址，所有人会共用同一条线路、同一套策略，
「一人一 IP」直接失效，且故障表现极其隐蔽（能上网、但线路和授权全错）。

## 2. 拓扑

```
        运营商 / 专线 CPE
                │
            [eth0]  WAN (DHCP 或 PPPoE)
        ┌───────┴────────┐
        │   N100 网关     │   LinkPilot 系统
        │  192.168.88.1   │   · 分流 / Kill Switch / 门户 8088
        └───────┬────────┘
                │ eth1..ethN（全部同属 br-lan，同一个二层域）
        ┌───────┴────────┐
        │  2.5G 交换机     │   （N100 有 4 口时可省）
        └──┬────┬────┬───┘
        [AP1]  [AP2]  [AP3]      均为桥接模式，同一 SSID
       .88.2  .88.3  .88.4       802.11k/v/r 开启
```

- N100 只有 2 个网口：`eth0` WAN，`eth1` 接交换机，3 台 AP 挂交换机。
- N100 有 4 个网口：`eth0` WAN，`eth1/2/3` 直接插 3 台 AP（固件已把它们全放进 `br-lan`，仍然是同一个二层域）。
- **不要**把 AP 插到 AP 的 LAN 口串成链（除了临时应急），串接会放大单点故障和链路瓶颈。

## 3. IP 规划（固件已固化，改动需同步 `10-linkpilot-base`）

| 用途 | 地址 | 说明 |
|---|---|---|
| 网关 / 门户 / DNS | `192.168.88.1` | 门户 8088；DHCP option 6 指向它，DNS 由 nftables DNAT 送进 tun |
| DHCP 池 | `192.168.88.100–199` | 100 个地址；12h 租约 |
| AP 管理地址 | `192.168.88.2 / .3 / .4` | 静态，**必须在池外**，不要用 DHCP 分配 |
| 运维保留 | `192.168.88.200–250` | 笔记本、编码器、临时调试 |
| 管理网段 | `lp.lan` 本地域 | dnsmasq 本地解析用，不对外 |

授权设备走「静态租约 + 源地址分流」：每个客户端在云端授权后由编译器生成固定 IP，Agent 落到 dnsmasq 静态租约。
所以终端 IP 是策略的一部分，**不要手工改**。

## 4. AP 侧配置（各品牌通用，不依赖固件）

每台 AP 只做这几件事，顺序照做：

1. **工作模式 = 无线接入点 / AP / 桥接**（不要选「路由模式」「中继 NAT」「WISP」）。
2. **LAN 口接交换机**（接上联口），**WAN 口空着不插**——很多机器插上 WAN 口就自动切成路由模式。
3. **关闭 DHCP 服务**（AP 自己不发地址，地址由 N100 发）。
4. **管理地址设为静态** `192.168.88.2/3/4`，网关填 `192.168.88.1`，DNS 填 `192.168.88.1`。
5. **SSID / 密码 / 加密方式三台完全一致**：同一 SSID、WPA2-PSK(AES) 优先。
   混用 `WPA2/WPA3 混合`时部分终端不会走 802.11r 快速漫游，宁可先用 WPA2 稳。
6. **关闭 AP 自带的 IPv6 / RA**（如果固件里有开关），IPv6 统一在 N100 上关。
7. **关闭「智能组网 / Mesh 自动优化」**这类厂商云功能：它们会自己改信道、自己开 DHCP，跟本方案冲突。
8. 2.4G / 5G 都可开，**同一个 SSID、不同频段**（band steering 交给终端，别开厂商的「双频合一强制」）。

### 4.1 信道规划（三台 AP）

| AP | 2.4GHz | 5GHz | 说明 |
|---|---|---|---|
| AP1 | ch 1 | ch 36 | 2.4G 只用 1/6/11 三个不重叠信道 |
| AP2 | ch 6 | ch 44 | |
| AP3 | ch 11 | ch 149 | 高信道避开 DFS 与 neighbour 扫描 |

**5G 宽带的硬约束**：80MHz 在 5G 低频段（36–48）只有 **一个**不重叠信道。三台 AP 都开 80MHz
必然同频重叠，漫游会互相打架。建议：

- 办公/直播场景优先 **5G 40MHz + ch 36/44/149**（实测吞吐足够，干扰可控）；
- 只有单台 AP 覆盖时才用 80MHz；
- 2.4G 统一 20MHz，仅供 IoT 与手机待机，别再压 40MHz。

### 4.2 漫游

- 开启 **802.11k**（邻居报告）、**802.11v**（BSS 过渡管理）、**802.11r**（快速切换）。
  三台 AP 必须都支持同一套，混品牌时 k/v 通常没问题，**r 经常不兼容**——不通就关 r，宁可慢 200ms 也别握手失败。
- 关闭 AP 侧的「弱信号剔除」除非你确认阈值（-70dBm 左右）；乱设会把正在直播的手机踢下线。
- 终端侧：**要求客户关掉该 SSID 的「私有 Wi-Fi 地址 / 随机 MAC」**。
  随机 MAC 会让设备每次连接换身份，静态租约匹配不上、门户认不出人，表现是「每次重连都掉线/要重新授权」。

## 5. N100 系统侧（已在本仓库实现）

| 项 | 实现位置 | 行为 |
|---|---|---|
| 系统 | `image/` | OpenWrt 24.10.8 x86_64，UEFI + squashfs，2GB overlay |
| 网口划分 | `etc/uci-defaults/10-linkpilot-base` | eth0→WAN，其余全部进 br-lan（按 PCI 顺序，支持 2/4 口） |
| LAN / DHCP / DNS | 同上 | 192.168.88.1/24，池 100–199，option 6 指向网关 |
| IPv6 关闭 | 三层 | wan6 不建 + DHCPv6/RA/ndp 关闭 + sysctl `disable_ipv6` |
| 多核软中断 | 同上 | `packet_steering=1`，N100 小包转发吃多核 |
| Agent | `etc/init.d/linkpilot` | procd 托管，崩溃重启，`paused` 标志可暂停 |
| 自检/救急 | `lp-status` / `lp-rescue` / `lp-enroll` | 见 `image/README.md` |

首次下发配置后，Agent 会用编译产物里的 nftables 规则**整体替换**系统规则集（这是 Kill Switch 的前提）。
副作用：规则里没放行的东西一律不通，包括 SSH 和 LuCI。现场失联就用 `lp-rescue`，不要拔电重刷。

## 6. 验收清单

系统层（刷完机、注册前）：

- [ ] `lp-status`：网口全 link、WAN 拿到上游地址、LAN 192.168.88.1 有响应
- [ ] `lp-status`：IPv6 无全局地址
- [ ] 2.5G 口实测协商 2500Mb/s（`ethtool ethX | grep Speed`）
- [ ] 待机功耗与温度：空载 10–15W、满载 CPU 温度 < 75℃（无风扇盒子重点看这条）
- [ ] 断电重启后自动起来（BIOS 来电自启）

接入层（接上 3 台 AP）：

- [ ] 3 台 AP 都能在 `192.168.88.2/3/4` 打开管理页
- [ ] 手机在 3 台 AP 之间走动，SSID 不变、直播不断（Roaming 生效）
- [ ] 客户端 `ip addr` 拿到的地址在 100–199，网关与 DNS 均为 `192.168.88.1`
- [ ] 客户端 `ip -6 addr` 无全局 IPv6 地址
- [ ] 从任一 AP 下的终端访问 `http://192.168.88.1:8088` 能打开门户
- [ ] 从 WAN 侧访问 8088 / 22 不通（这是对的）

业务层（需要云端配合）：

- [ ] 设备注册成功、云端出现在线
- [ ] 首次下发 `sing-box check` / `nft -c -f` 均为 ok（真机第一次才算数）
- [ ] 授权终端走代理线路、未授权终端只能访问门户
- [ ] 拔掉主线路，新连接在多少秒内恢复（记下来，这是对客户的承诺基线）

## 7. 待确认（不做完这些不要对外承诺）

1. **AP 型号与固件**：是否支持 802.11k/v/r、5G 是否支持 40/80MHz 手选、能否真正关掉 DHCP 与 IPv6 RA。
   若三台是同型号且能刷 OpenWrt，可以统一配置模板，比厂商固件可控得多。
2. **N100 网口芯片**：i226-V（`igc`）与 RTL8125（`r8169`）都在固件默认驱动里；若是少见芯片，`lp-status` 会显示端口没识别。
3. **上行类型**：DHCP 还是 PPPoE。PPPoE 需要在 `10-linkpilot-base` 里改 `network.wan.proto`（文件内有注释示例）。
4. **是否要 2.5G 交换机**：3 台 AP 若都是千兆口，用千兆交换机即可；要跑满 2.5G 上行则交换机不能是瓶颈。
5. **AP 供电与布线**：PoE 交换机可省掉 3 个电源适配器，也少 3 个故障点。
