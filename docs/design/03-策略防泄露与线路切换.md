# 策略、防泄露与线路切换

> ⚠️ 适用范围变更（2026-11-14）：本文的"客户端之间禁止互访"依赖「无线由网关自己发射」的前提。
> 交付形态改为 **N100 网关 + 外置 AP** 后，同网段二层流量不经网关，网关 nft 规则看不见，
> 隔离必须由 AP（AP isolation）或按 SSID 分 VLAN 后由网关做三层隔离实现。
> 详见 `10-N100-系统基线与稳定性设计.md` §13。本文其余内容仍然有效。

## 1. 设计思路

先把用户可理解的模式转换为确定性的 `RouteProfile`，再编译为本地快速匹配结构。数据包转发路径不访问数据库、不等待云端，也不依赖前端隐藏菜单。

## 2. V1 分流模式

| 模式 | 规则语义 | 默认可见范围 |
|---|---|---|
| 严格全局代理 | 允许的公网 TCP/UDP/QUIC 均进入代理链路，代理不可用则阻断 | 客户和管理员 |
| 大陆直连/其他代理 | 大陆域名/IP 直连，其余公网流量走代理 | 客户和管理员 |
| 自定义策略 | 按设备、账号、域名、IP、端口、协议和线路匹配 | 管理员，客户按授权范围 |
| 全部直连 | 仅用于诊断或维护 | 默认仅运营管理员及以上 |

“大陆直连”规则必须遵守当地法律、业务合规和用户明确授权，不宣传规避监管或安全审查。

## 3. 固定规则优先级

```text
局域网和设备管理例外
→ 强制阻断
→ 设备/账号专属规则
→ 管理员自定义规则
→ 白名单直连
→ 指定线路
→ 大陆直连
→ 默认线路
```

同优先级冲突时采用显式优先级、最长匹配和稳定的规则 ID 排序。编译器必须拒绝不可判定的冲突，而不是依赖执行器偶然行为。

## 4. DNS 防泄露

### 4.1 强制路径

- DHCP 下发软路由 DNS 地址。
- nftables 将客户端 UDP/TCP 53 重定向到本地 DNS 服务。
- 硬编码外部 DNS 由默认拒绝规则阻断或按管理员策略受控放行。
- DoT/DoH 采用可配置的阻断、受控代理或明确白名单策略。
- 直连解析和代理解析使用不同上游、缓存分区和策略标签。
- GeoIP、GeoSite 和自定义规则以版本化资源发布，更新失败保留上一版本。

### 4.2 DNS 失败策略

DNS 上游不可用时，不得退回未受控的 WAN DNS。根据 RouteProfile 选择备用受控 DNS；全部失败则返回失败并维持 Kill Switch，避免通过外部解析造成泄露。

## 5. IPv6 防泄露

V1 默认关闭 IPv6：

- WAN 不获取 IPv6 前缀和地址。
- 关闭 DHCPv6 和 Router Advertisement。
- 禁止 LAN 向客户端发布 IPv6。
- nftables IPv6 默认拒绝公网转发。
- 启动自检和周期探针检查客户端、WAN 和出口 IPv6。

未来支持 IPv6 前，必须实现 IPv6 TUN/透明代理、DNS 处理、策略路由、Kill Switch 和同等验收测试；不能只恢复 IPv6 通信。

## 6. Kill Switch

采用默认拒绝、白名单放行：

```text
允许：DHCP、ARP、门户、必要控制通道、已验证代理服务器、已进入代理链路的流量
拒绝：未进入代理链路的普通 WAN 直连、未授权设备公网访问、异常状态下的绕行流量
```

以下情况立即维持或进入阻断状态：

- 代理核心停止或配置校验失败；
- 当前线路和备用线路均未通过最低健康检查；
- 策略版本不完整、签名失败或版本回退异常；
- 本地防火墙和路由状态与期望摘要不一致。

门户、局域网 DHCP 和必要的本地诊断仍应保持可用。Watchdog 只能执行固定恢复动作，不得绕过默认拒绝规则。

## 7. 健康状态机与自动切线

```text
HEALTHY
  └─连续失败达到预警阈值→ DEGRADED
       └─达到失败阈值→ FAILED
            ├─备用验证失败→ BLOCKED/FAILED
            └─备用验证成功→ SWITCHING
                              └─应用新连接策略→ ACTIVE_STANDBY
                                    └─主线路连续稳定→ RECOVERY_OBSERVING
                                          └─达到恢复阈值→ HEALTHY
```

### 状态和锁

- `FailureThreshold`：连续失败次数或时间窗口。
- `RecoveryThreshold`：连续成功次数或时间窗口。
- `Cooldown`：切换后的最短冷却时间。
- `Hysteresis`：失败和恢复使用不同阈值。
- `MaxSwitchPerHour`：防止线路抖动导致反复切换。
- `LeaseLock`：门户、后台和本地自动切换之间的互斥租约。
- `FencingToken`：旧任务完成时不得覆盖新线路状态。
- `MaintenanceMode`：维护期间暂停自动切换或限制切换范围。
- `ManualPin`：管理员手动锁定线路，必须记录过期时间和原因。

### 切线原则

- 备用线路先做端口、协议握手、代理出口和业务目标预检。
- 新连接使用备用线路；已有连接保持粘滞，除非管理员选择立即切换。
- 立即切换明确提示可能中断当前直播。
- 每次切换记录原因、旧线路状态、新线路状态、检测时间、配置版本和结果。

## 8. 本地探针和云端探针

本地探针检查设备现场：系统资源、WAN/LAN、DHCP、DNS、门户、Agent、代理进程、协议握手、代理出口、实际 HTTPS、延迟、丢包、抖动和吞吐。

云端探针检查平台视角：Agent 在线状态、控制通道、线路服务端可达性、跨地区质量、DNS、业务目标以及多设备共同故障。

测速任务必须限频、限时、限速并与直播流量隔离；默认不采集完整流量内容，不记录敏感凭证。

诊断树固定为：

```text
设备电源/系统 → 网卡/WAN → DHCP/DNS → 代理进程 → 节点握手 → 出口 IP → 业务目标
```
